원본 CSV에서 고객 ID를 연결하고 `customer_unique_id`만으로 주문 수를 집계하면 다음과 같습니다. 상품 내부 조인이나 과거 DB 정제는 적용하지 않았습니다.

| 주문 상태 범위 | 고유 고객 | 1회 구매 | 2회 이상 구매 |
| --- | ---: | ---: | ---: |
| 전체 | 96,096 | 93,099 | 2,997 |
| delivered·shipped·processing | 94,686 | 91,814 | 2,872 |
| delivered | 93,358 | 90,557 | 2,801 |

약 97%가 1회 구매라는 방향은 공통이지만 정확한 분모는 다릅니다. 재구매하지 않은 고객을 영구 이탈 고객으로 확정하지 않습니다. 관측 종료에 가까운 신규 고객은 후속 구매를 관찰할 시간이 짧습니다.

평점에서 학습 라벨을 만들었기 때문에, 모델과 평점의 불일치는 **사람이 검토할 후보**입니다. 텍스트의 실제 감정, 개선 성공 확률, 재구매 가능성을 확정하는 결과가 아닙니다. 후보 추출에는 학습에 사용한 리뷰도 포함돼 있습니다.

### 모델 성능 표기

PDF 15쪽은 TF-IDF 최대 5,000개 피처와 `LogisticRegression(max_iter=200)`의 정확도 **0.917**, 부정 F1 **0.857**, 긍정 F1 **0.942**를 제시합니다. 로컬 노트북의 평가 출력에는 정확도 **0.904**가 남아 있어 서로 일치하지 않습니다.

현재 코드에는 다음 재현·평가 과제가 있습니다.

- TF-IDF를 전체 라벨 데이터에 `fit_transform`한 뒤 학습·평가 데이터를 나눠 평가 데이터의 어휘·IDF 정보가 전처리에 반영됩니다.
- 평가 셀이 참조하는 `y_pred`의 선행 생성 코드가 누락돼 있습니다. 저장된 출력만으로 순차 실행을 보장하지 않습니다.
- 평점 유래 라벨은 독립적인 텍스트 감정 정답이 아닙니다. 중립 리뷰는 학습에서 제외돼 있습니다.

따라서 91.7%를 검증 완료된 현재 모델 성능으로 대표 제시하지 않습니다. 후속 평가에서는 원문을 먼저 분리하고 TF-IDF·분류기를 Pipeline으로 학습하며, 고객·리뷰 중복과 사람이 검수한 텍스트 라벨을 확인해야 합니다.

### ‘전환 가능 고객 4,493명’을 대표 성과로 사용하지 않는 이유

감정 예측 노트북의 ‘실제 고객 수 계산’ 셀은 고평점·부정 예측 리뷰 ID를 `[:1000]`으로 제한합니다. 세부 그룹 계산도 `[:500]`을 사용합니다. PDF 19쪽의 4,493명과 그룹별 497·495·494명은 전체 후보를 완전 집계한 결과로 취급하기 어렵습니다.

후속 고객 매핑은 `review_id`만으로 조인합니다. 원본에서 이 키는 유일하지 않아 행이 늘거나 고객이 잘못 연결될 가능성이 있습니다. 검토한 로컬 결과 파일은 다음과 같습니다.

| 로컬 파일 | 행 수 | 비결측 고유 고객 ID | 고객 ID 결측 행 | 완전히 같은 중복 행 |
| --- | ---: | ---: | ---: | ---: |
| `conversion_candidates_with_customer_id.csv` | 4,856 | 4,711 | 14 | 114 |
| `comprehensive_conversion_analysis.csv` | 5,325 | 4,711 | 14 | 570 |

두 파일 모두 고유 `review_id`는 4,742개입니다. **4,711명도 올바른 고객 매핑이 검증된 확정 대상 수로 대체하지 않습니다.** 후속 집계는 `order_id`를 포함한 리뷰 식별 기준과 고객 매핑을 검증하고, 고객별 중복 제거·대표 이슈 규칙을 정한 뒤 수행해야 합니다.

## 3. ROI와 CLV 시나리오

근거는 [고객 시나리오](../01.analysis/06_Review/03.고객시나리오.ipynb)와 PDF 20–21쪽입니다. 주요 입력과 결과를 분리하면 다음과 같습니다.

| 구분 | 내용 |
| --- | --- |
| 관측 지표 | 만족도별 저장 재구매율: High 3.11%, Low 2.81%, 차이 0.30%p |
| 대상 분류 | 포르투갈어 키워드로 크기·색상 → 배송비·가격 → 기대 불일치 순서로 단일 이슈 부여 |
| 시나리오 가정 | 보수적 만족도 전환 20%, 낙관적 35%, 관측 재구매율 차이에 각각 0.8·1.0 배수 적용, 2년, 코드상 구매 계수 1.2 |
| 비용 가정 | 기본 1인당 R$140, 조정 후 이슈별 R$60·30·40 |
| 누적 가치 | `total_gmv` 평균을 `avg_clv`로 사용. 미래 고객 순이익을 예측한 CLV와 구분 |

당시 산식은 아래와 같습니다.

```text
개선 전환 수 = 대상 행 수 × 시나리오 전환율
예상 추가 주문 = 개선 전환 수 × 재구매 차이 가정 × 1.2 × 기간
예상 추가 거래액 = 예상 추가 주문 × 평균 AOV
투자비 = 대상 행 수 × 1인당 비용
거래액 기반 ROI = (예상 추가 거래액 - 투자비) / 투자비 × 100
```

저장된 보수적 결과는 기본 비용에서 약 -99.9%, 조정 비용에서 약 -99.6∼-99.8%였습니다. **실제 사업 ROI가 아니라 위 입력에 의존한 시나리오**입니다. 원천 후보 CSV의 중복이 남아 있고 코드가 `len()`을 사용하므로, 이슈별 643·223·895는 고유 고객으로 검증된 수가 아닙니다.

다음 사항 때문에 투자 판단을 확정할 수 없습니다.

1. 만족도별 관측 재구매율 차이는 만족도 개선의 인과효과가 아닙니다.
2. 거래액은 플랫폼 이익과 다릅니다. 수수료율·마진·반품·CS 비용·할인율·개입 비용 실측이 필요합니다.
3. `CLV = 누적 거래액`은 관측기간의 대용 지표입니다. `투자비 / 전환 고객 수`와 과거 누적 거래액의 비교만으로 신규 투자 회수를 입증하지 못합니다.
4. PDF와 코드에는 서로 다른 시나리오 입력이 혼재합니다. 코드에서 확인되는 재구매율 차이는 0.30%p이며, 발표 텍스트의 다른 증가율 가정을 실측 성과로 사용하지 않습니다.

PDF의 ‘크기·색상 고객은 R$55.70만 더 구매하면 손익분기’, ‘배송비·가격은 즉시 수익화 가능’은 당시 대용 지표 산식의 해석입니다. 이번 문서에서는 **비용 회수 조건의 탐색**으로 설명하고, 수익화 검증 성과로 사용하지 않습니다.

## 4. 셀러 퍼널과 거래액

근거는 [매출 성과 분석](../01.analysis/07_Marketing/03.매출성과분석.ipynb), PDF 28–30쪽입니다.

| 지표 | 과거 정제 DB 저장 결과 | 원본 CSV 재집계 |
| --- | ---: | ---: |
| MQL | 8,000건 | 8,000건 |
| 계약 리드·판매자 | 842건·842명 | 842건·842명 |
| 주문상품에서 거래가 관측된 계약 판매자 | 379명 | 380명 |
| 해당 판매자 GMV | R$774,045.31 | R$775,815.63 |
| 계약률 | 842 / 8,000 = 10.525% | 동일 |
| 계약 판매자 중 거래 관측 비율 | 379 / 842 ≈ 45.0% | 380 / 842 ≈ 45.1% |
| 전체 리드 대비 거래 관측 판매자 비율 | 379 / 8,000 ≈ 4.7% | 380 / 8,000 = 4.75% |

GMV는 이 분석에서 `SUM(price + freight_value)`입니다. 다른 고객 분석의 상품금액 합계와 혼용하지 않으며, Olist의 순매출·이익으로 해석하지 않습니다. 원본 재집계는 계약 판매자와 주문상품의 연결만 적용했고, 주문 상태와 계약 이후 기간 필터는 적용하지 않았습니다.

저장 출력에서 정제 주문상품은 112,240행으로 원본 112,650행과 다릅니다. 두 결과의 차이를 구분하되, 어떤 제외 행이 차이를 만들었는지는 당시 DB 스냅샷을 재구축해 추가 확인해야 합니다.

또한 다음 해석을 제한합니다.

- PDF 28쪽 퍼널의 Contact 35%·Qualified 60%는 명시된 가정입니다. 실제 단계별 관측값으로 사용하지 않습니다.
- 계약일과 주문일을 맞춘 고정 관측기간 분석이 아니므로 379명을 ‘계약 이후 일정 기간에 활성화된 판매자’로 단정하지 않습니다.
- 노트북의 `roi_score`는 `계약률 × 리드당 GMV / 100`입니다. 채널별 실제 마케팅비를 반영한 ROI가 아닙니다.
- ‘LTV’로 표시한 채널별 평균 GMV는 관측 거래액 지표이며 미래 생애이익과 다릅니다.
- 성과 예측 노트북의 저장 출력은 병합 후 리드 8,380행·전환 1,222행으로 원본 고유 리드·계약 수와 다릅니다. 별도 CSV 기반 노트북과도 평가값이 다릅니다. 고유키·중복·분할·예측 시점 변수를 검증하기 전 성능을 대표 성과로 사용하지 않습니다.

## 5. 대시보드와 ETL 완료 범위

[데이터마트 노트북](../02.ad_hoc/00.데이터마트생성.ipynb)은 DM 6종·DIM 4종·AGG 4종의 14종 CSV 출력을 설계합니다. 단독 집계 실행에는 4종 저장 성공 로그가 있지만 전체 실행 로그에는 SQL 문자열 형식 처리 오류와 `성공: 3/8개`가 남아 있습니다. 이 8개는 함수 그룹 수이며 CSV 파일 수가 아닙니다.

검토 시 로컬 `data/`에는 설계 목록 중 13종 이름의 CSV가 있고 `dm_action_planner.csv`는 없습니다. 파일 존재와 저장된 과거 실행 로그는 현재 코드 전체 실행 성공의 증명이 아닙니다.

PDF 24쪽은 Tableau 대시보드를 ‘진행중’으로 표시하며, KPI Overview 구성 화면이 포함돼 있습니다. 이 화면을 [원본 이미지](assets/tableau-kpi-overview.png)로 추출했습니다. 표시된 고객 수·AOV·만족도 등은 당시 화면을 보존한 값이며 이번 문서화에서 재계산한 KPI가 아닙니다.

현재 로컬 [워크북](../03.dashboard/storyboard_.twb)을 확인한 결과 `01.서론`, `02.KPI개요` 대시보드 2개와 워크시트 8개가 있습니다. 워크북 존재와 구조를 확인했으므로 앞서 ‘워크북 없음’으로 기술했던 내용을 바로잡았습니다. Tableau 앱에서 데이터 재연결·필터와 액션·공개 배포 동작까지 검증한 것은 아닙니다. 표지의 프로필 링크만으로 공개된 완성 대시보드를 특정하지 않았습니다.

## 6. 후속 KPI·What-if 코드의 지표

[월별 KPI](../03.dashboard/monthly_KPI.ipynb)는 `dm_kpi_overview.csv`의 `repeat_rate_pct`를 사용합니다. 추출 SQL의 분모는 해당 월 고유 구매 고객이며, 분자는 첫 구매일보다 **날짜가 이후인 구매**가 있는 고객입니다. 같은 날의 두 번째 구매는 이 조건에 포함되지 않으며, 같은 달에 첫 구매와 후속 구매를 한 고객은 신규·재구매 양쪽에 포함될 수 있습니다. 신규·재구매 고객 수를 배타적인 두 그룹의 합으로 해석하지 않습니다.

월별 KPI는 Matplotlib 2×2 화면과 요약 함수의 구현입니다. 코호트 리텐션이나 전체 기간의 2회 이상 구매 비율과는 다른 지표입니다. 입력 CSV의 다중 조인·리뷰 중복은 GMV·평균 평점에도 영향을 줄 수 있어, 코드가 존재한다는 사실과 KPI 정확성 검증을 구분합니다.

[What-if](../03.dashboard/What-if.ipynb)는 평점 그룹별 DB 집계와 별도로 고정한 기준값·개선폭·비용을 사용합니다. 3년 할인 거래액과 민감도를 계산하지만 실제 개입 효과를 측정한 결과나 완성된 인터랙티브 입력 UI는 아닙니다. 후속 대상 조회 함수는 감정 테이블을 전제로 하는 코드도 있어 현재 DB 스키마 대조가 필요합니다.

BI 액션 플래너 SQL의 `expected_roi`에는 시나리오별 상수가 직접 들어 있습니다. 해당 값을 계산·검증된 투자 수익률로 인용하지 않습니다.
